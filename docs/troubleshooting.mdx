Start with the built-in checks:

```bash
envshare doctor --verbose
```

This tests your clock, private file output, DNS, TCP, QUIC, discovery, and the
public relay without using a real share code.

<AccordionGroup>
  <Accordion title="envshare: command not found">
    Check whether the binary is installed:

    ```bash
    ls "$HOME/.local/bin/envshare"
    ```

    If it exists, add `$HOME/.local/bin` to `PATH` and open a new terminal. See
    [installation](/installation) for the exact command.
  </Accordion>

  <Accordion title="private output failed">
    Envshare could not safely create or update the destination. Check that:

    - you can write to the current folder;
    - the destination is a regular file, not a symlink or directory;
    - the filesystem is not read-only;
    - no other process has locked the file; and
    - there is free disk space.

    Try a new path:

    ```bash
    envshare receive --output .env.received
    ```

    Add secret-safe diagnostics when needed:

    ```bash
    envshare --log debug receive
    ```
  </Accordion>

  <Accordion title="share not found or unauthorized">
    Re-enter the full code and confirm both computers use the same network. The
    same message can also mean the share expired, was cancelled, or was already
    claimed. Envshare intentionally does not reveal which case occurred.
  </Accordion>

  <Accordion title="network operation failed">
    Run `envshare doctor --verbose`. Confirm that outbound TCP and UDP are
    allowed and that DNS resolves `node.envshare.xyz`. VPNs, corporate firewalls,
    and some guest networks may block UDP; TCP should remain available.
  </Accordion>

  <Accordion title="the sender never shows a code">
    The public profile waits for a relay reservation and discovery registration
    before revealing the code. Run `envshare doctor --verbose` from the sender.
    If the public node is unavailable, wait and try again or use a self-hosted
    network profile.
  </Accordion>

  <Accordion title="the file may have arrived, but confirmation failed">
    Inspect the chosen destination. Do not retry the same code to another path.
    The receiver may have written the file before its final acknowledgement was
    lost.
  </Accordion>
</AccordionGroup>

## Collect useful diagnostics

```bash
envshare --version
envshare doctor --verbose
envshare --log debug receive
```

Envshare's diagnostic events are designed to omit codes and payload data. Still,
read the output before sharing it publicly. Never attach a real `.env` file.

If the problem persists, open a
[GitHub issue](https://github.com/envoy1084/envshare/issues) with the operating
system, Envshare version, command, safe diagnostic output, and expected result.
